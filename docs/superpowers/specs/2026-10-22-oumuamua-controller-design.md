# oumuamua コントローラ設計書

- 日付: 2026-10-22
- 状態: 確認待ち(oumuamua main 563c34d の gripper / task_commander を反映)
- 対象ロボット: [oumuamua](https://github.com/Stew-000-1-0-011/oumuamua)(ROS 2 Lyrical、3 輪オムニ)
- 使う場面: 学祭での運用

## 1. 目的

同じ Wi-Fi につないだ Android スマホから、oumuamua を UDP で操作・監視する。画面は 3 面(出力、手動制御、自動制御)を重ね、画面端の切り替えで選ぶ。

## 2. 構成

- **スマホアプリ**(Rust + Slint 1.18、Android。PC でも動かせる)
  - `proto`: メッセージの定義と符号化(MessagePack、`rmp-serde`)。
  - `link`: UDP、生存確認の送信、確実に届ける流れ(再送)。UI とは別スレッドで動く。
  - `app`: 画面。
- **橋渡しノード**(ROS 2 パッケージ `oumuamua_controller_bridge`、Python、`ament_python`)
  - ROS のトピック・サービスとやりとりし、スマホとは UDP で話す。
  - シェルのタブ(疑似端末上の bash)を動かす。
  - oumuamua にこのリポジトリをサブモジュールとして入れ、一緒にビルドする。
- **メッセージ形式の一致**: Rust と Python の両方で、同じ見本のバイト列(リポジトリに置く)を読み書きできることをテストで確かめる。

## 3. 接続

- 橋渡しノードは UDP 47800 で待つ。1 秒ごとに 47801 へ名乗り(ロボット名、ポート)を同報する。
- スマホは名乗りの一覧から選ぶか、IP アドレスを打って接続する。最後の接続先を覚える。
- 同時に操作できるスマホは 1 台。別のスマホは「操作を引き継ぐ」を押したときだけ乗っ取れる(前のスマホには乗っ取られたことを表示する)。
- 認証はしない。後から足せるよう、接続の最初のメッセージに予備の欄を置く。

## 4. 通信

1 本の UDP の上に、3 つの流れを載せる。1 パケットは 1200 バイト以下。

### 4.1 操縦と生存確認(スマホ → ロボット、50 回/秒、再送なし)

- 番号、送信時刻、並進速度 (vx, vy)、旋回速度 ω、座標の基準(ロボット/フィールド)、左右の昇降の「上」「下」、全停止の状態。吸引の入り切りや棚の高さへの移動は、確実に届ける流れ(4.3)で送る。バイトの並びは `docs/protocol.md`。
- 古い番号のものは捨て、最新だけを使う。
- 往復の遅延は、ロボットが返す状態に「最後に受けた番号と時刻」を載せて測る。

### 4.2 状態(ロボット → スマホ、再送なし)

- 20 回/秒: 位置と向き、速度、モード(手動/自動/停止)、経路追従の状態(経路名、進み具合)、追従の入り切り、各車輪の電圧と状態、昇降の高さ、吸引の状態、最後に受けた操縦の番号と時刻。
- 10 回/秒: LiDAR(`/scan`)。距離を mm の整数にし、1 パケットに収まるよう間引く(足りなければ分割する)。

### 4.3 確実に届ける流れ(双方向)

- 番号付きで、受けた側が受信済みの番号を返す。100 ms 返事がなければ再送する。順番どおりに渡す。
- 載せるもの: コンソールの入出力、ROS のログ(`/rosout`)、自動制御の要求とその結果、経路の形、フィールドの形、昇降の止まる高さの一覧、経路の一覧。
- コンソールの大量の出力で操縦が遅れないよう、送る量に上限を設ける(未確認の分が一定量を超えたら送るのを待つ)。

## 5. 安全

### 5.1 全停止

- 中身: task_commander の作業を取り消す、`/path_follower/stop`、`/tracker_node/enable` を false、速度 0 の `/cmd_vel` を 50 回/秒で出し続ける、昇降の動きを取り消してその場で止める、**左右の吸引を切る(`/gripper<i>/set_suction` false。箱は落とす)**。
- 一度入ると、スマホの「解除」を押すまで停止のまま。
- 全停止ボタンは 3 面すべてで、右端の帯に常に表示する。

### 5.2 通信が切れたとき

- 操縦の信号が 0.3 秒届かなければ、橋渡しノードが全停止に入る(自動走行中も)。
- つなぎ直しても停止のまま。スマホで解除する。

### 5.3 手動と自動の取り合い

- 橋渡しノードはモード(手動/自動/停止)を持つ。`/cmd_vel` を出すのは手動のときだけ。
- 自動制御の面から作業か経路を始めると自動になる。自動の間、手動制御の面には「自動走行中(作業名か経路名、今の段階)」のポップアップを重ね、操作部には触れられない。ポップアップの「手動制御へ」を押すと、作業を取り消し、経路を止め、追従を切り、手動にする。
- 作業や経路が終わる(成功・失敗・取り消し)と、手動に戻る。
- 手動の間、スティックを離していれば速度 0 を出し続ける。

## 6. 画面

- 横向き。右端に縦の帯を置き、上から「出力・手動・自動」の切り替え、接続状態(つながっているか、往復の遅延)、全停止(停止中は解除)を並べる。
- タップの的は 44px 以上。文字は同梱の日本語フォントで出す。

### 6.1 出力の面

- **地図**(左): 上から見下ろした 2D。フィールドの壁、ビンゴ棚、ロボット(外形と向き)、LiDAR の点、走っている経路、追従の目標。指 2 本で拡大・縮小・移動、ボタンで全体表示に戻す。
- **数値の帯**(上): 位置、速度、各車輪の電圧、モード。
- **コンソール**(右): 7 章。入力欄に触れると、専用キーボードが画面の下側に出る。

### 6.2 手動制御の面

- **左**: 並進のスティック。指を離すと 0。
- **右**: 旋回の横スライダー。指を離すと 0。
- **中央**:
  - 速度の段階: 低・中・高(初期値: 並進 0.3/0.8/1.5 m/s、旋回 1.0/1.8/2.5 rad/s。橋渡しノードの設定で変えられる。経路の上限 2.0 m/s・2.5 rad/s を超えない)。
  - 座標の基準: ロボット基準/フィールド基準。フィールド基準の変換は、最新の推定姿勢を持つ橋渡しノードで行う。
  - 左右の昇降: 「上」「下」(押している間だけ動く)と、棚の高さのボタン(9 章)。左右を同時に動かす「両方」の切り替え。今の高さと目標を数字で示す。
  - 左右の吸引: 入り切り。状態を色で示す。
  - **リセット**: 長押し(1 秒)で、昇降の今の位置を 0 点とする(`~/zero_lift`)。動いている間は受け付けない。
- 自動の間は、5.3 のポップアップを重ねる。

### 6.3 自動制御の面

作業は task_commander の `~/run`(`RunTask`)に送る。作業中に次の作業は送れない(ボタンを押せなくする)。

- **回収(PICK)**: ノーツゾーンのブロック 6 個を並べた図(番号 0 が外周壁の側)から 1 つ選び、把持機構(左/右)を選んで「回収」。回収済みのブロックは押せなくする。
- **配置(PLACE)**: 棚の 3×3 のマス(列 0..2、段 0..2)から 1 つ選び、ブロックを持っている把持機構(左/右)を選んで「配置」。置いたマスには印を付ける。2 段目より上で、同じ列の下の段に自分で置いていなければ注意を出す(止めはしない)。
- **移動**: 「スタートへ」「スラロームの入口へ」「スラロームの出口へ」「スラローム往路」「スラローム復路」。
- **作業中の表示**: 作業名、今の段階(フィードバックの `step`)、地図(出力の面と同じもの)。「取り消し」ボタン。
- **覚えていることの表示**: どちらの把持機構が持っているか、回収したブロック、置いたマス(`/task_commander/state`)。「忘れさせる」(長押し、`/task_commander/reset`)。
- **経路**(下のほうに小さく): `/path_follower/start/<名前>` の一覧から並べる。押すと追従を入れてから経路を始める。走り出せなかったとき(始点から遠いなど)は理由を表示する。経路の停止、追従の入り切りも置く。
- **自己位置の指定**: 地図を長押ししてそのままドラッグし、位置(押した点)と向き(ドラッグの方向)を決める。離すと確認を出し、「決定」で `/initialpose` を送る。スタート地点に合わせたいときもこれで行う。
- 結果(成功/失敗と理由)は画面下に表示し、ROS ログのタブにも記録する。

## 7. コンソール

### 7.1 タブ

- タブ 1 つにつき、ロボット側で疑似端末上の bash を 1 つ動かす。タブには名前を付ける(英数字、`_`、`-`)。名前は重ならない。
- 追加・名前変更・閉じるができ、左右のスワイプで切り替える。**閉じるとロボット側の bash も終了する**(SIGHUP)。
- 通信が切れてもロボット側の bash は動き続け、つなぎ直すと直近の出力(タブごとに 2000 行)を受け取って続きから表示する。
- 先頭に、ROS のログ専用のタブ(閉じられない)を置く。重要度で絞り込める(初期値は INFO 以上)。

### 7.2 入力

- 行の編集はスマホの中だけで行い、編集中は何も送らない。
  - 文字の挿入と削除、カーソル移動、Ctrl+A/E(行頭/行末)、Ctrl+W/U(単語/行頭まで削除)、Ctrl+L(表示を消す)。
  - 履歴: ↑↓ で呼び出し、Ctrl+R で検索。タブごとの履歴と、全タブ共通の履歴の両方を持ち、スマホに保存する。
- **Enter**: その行をロボットに送る。
- **Tab**: その行を送り、補完の候補を返してもらう。候補は、そのタブの bash と同じ作業フォルダで、bash の補完機能(ROS の補完を含む)を使って作る。1 つならそのまま入れ、複数なら入力欄の上に並べてタップで選ぶ。
- **すぐ送るもの**: Ctrl+C(中断)、Ctrl+D(入力の終わり)、Ctrl+Z、Ctrl+\。それ以外の Ctrl の組み合わせのうち、スマホで処理しないものもすぐ送る。
- 1 行ずつ入力を受けるプログラム(`python3` の対話モードなど)は使える。画面全体を書き換えるプログラム(`vim`、`top`)は扱わない。
- よく使うコマンドを 1 タップで入れるボタン列を置く。内容は自分で編集でき、スマホに保存する。

### 7.3 出力

- 改行、復帰(CR)、後退、色(16 色と 256 色)、行の消去を解釈する。それ以外の制御の並びは捨てる。
- 長い出力(初期値: 1 回の実行で 30 行超)は折りたたみ、タップで開く。
- スマホ側はタブごとに 5000 行まで持つ。

### 7.4 記録

- ロボットの `~/.oumuamua_controller/console/<タブ名>/<開始日時>.log` に、時刻付きで入力した行と出力を残す。
- 同じ名前のタブを開き直すと、同じフォルダに新しいファイルを作って続ける。

## 8. 専用キーボード

- コンソールの入力中は OS のキーボードを使わず、アプリが描く。
- 配列: QWERTY と数字、Shift、記号の面への切り替え。上に 1 段、Esc・Tab・Ctrl・Alt・← ↑ ↓ →・`|`・`~`・`-`・`/` を並べる。
- Ctrl と Alt は、1 回押すと次の 1 キーだけに効き、2 回押すと固定する。
- 後退と矢印は長押しで繰り返す。
- 高さは画面の 4 割程度。出ている間、コンソールは残りの部分に縮めて表示する。

## 9. 昇降の止まる高さ

- 今年のルール(千葉大ロボコン 2026、修正後)のビンゴ棚: 3 段。棚板の上面は最下段 0.00 m、中段 0.34 m、上段 0.68 m。
- ボタンはその +1 cm の **0.01 / 0.35 / 0.69 m** で止める(「下段」「中段」「上段」と「0 点」)。gripper の `~/move_lift`(高さを直接指定するアクション)で動かす。
- 昇降の高さは gripper の定義どおり「起動時の位置を 0 とした高さ」(gripper.yaml の想定では、吸っているブロックの下面の高さ)。高さの一覧は橋渡しノードの設定に置き、接続時にスマホへ送る。
- gripper の `lift.max_height`(今は暫定の配線で 0.19 m)を超える高さのボタンは押せなくし、理由を表示する。
- 「上」「下」は、押したら `~/move_lift` で上限/下限へ向かうゴールを送り、離したら取り消す(取り消すとその時点で止まる)。

## 10. ロボット側の口(橋渡しノードがつなぐ先)

- 走行: `/cmd_vel`、`/path_follower/start/<名前>`・`/stop`・`~/path`、`/tracker_node/enable`・`~/reference`、`/state_estimator/odom`、`/initialpose`、`/scan`、`/wheel<i>/status`、`/rosout`。
- 作業: `/task_commander/run`(アクション `task_commander/action/RunTask`)、`/task_commander/state`(`std_msgs/String`、transient local)、`/task_commander/reset`。
- 昇降と吸引: `gripper0`(左)、`gripper1`(右)。task_commander.yaml の取付位置(機体座標系で y = +0.12 が gripper0)から、左右をこう対応させる。
  - `~/move_lift`(アクション、高さ [m])、`~/set_suction`(SetBool)、`~/enable_lift`(SetBool)、`~/state`(`gripper/msg/GripperState`)。
- 昇降の 0 点: gripper_node の `~/zero_lift`(`std_srvs/Trigger`。robomas_plugins の `/robomas_zero_position` を呼び、指令・ゴール・回転の数え上げを 0 にそろえる)を使う。これは oumuamua 側で足す前提で、まだ無い。サービスが無ければ、リセットは失敗として理由を表示する。
- 橋渡しノードの package.xml は `gripper`、`task_commander`、`path_follower` に依存する(oumuamua のワークスペースで一緒にビルドする前提)。
- フィールドの形は、sotoba の定義(`objects.cpp`)と同じ線分の一覧を橋渡しノードの設定に持ち、接続時に送る。

## 11. 確認の方法

- PC で、oumuamua の `sim:=true` と橋渡しノードを動かし、PC 版のアプリで全機能を確かめる。
- テスト:
  - `proto`: Rust と Python で見本のバイト列が一致する。
  - `link`: パケットの欠落・重複・入れ替わりがあっても、確実に届ける流れが順番どおりに届く。
  - 橋渡しノード: 0.3 秒の途切れで全停止に入る(作業の取り消しと吸引オフを含む)、解除まで停止のまま、自動の間は `/cmd_vel` を出さない。
  - コンソール: 行の編集、補完、Ctrl+C、タブを閉じると bash が終わる、記録ファイルができる。
- 実機では、まず車輪を浮かせて、通信が切れたときに止まることを確かめる。
