# Slint のマルチタッチ対応 設計書

- 日付: 2026-10-23
- 状態: 承認済み(4 つの扱いはユーザー確認済み)
- 対象: Slint 1.18.1 の i-slint-core(コントローラでは `=1.18.1` に固定)

## 1. 目的

手動制御の面で、並進のスティックと旋回のスライダーを別々の指で同時に動かせるようにする。各部品に触れる指は常に 1 本とし、別々の部品なら複数の指を同時に受ける。

## 2. 今の Slint の動き(1.18.1)

- Android の土台は全部の指を番号付きで中核へ渡している(`InternalEvent::Touch`)。
- 中核の `TouchState`(`input.rs`)が 1 本目を「主」としてマウスとして流す。2 本目が来ると主を離した扱いにし、2 本からピンチ・回転を合成する。3 本目以降は捨てる。
- ウィンドウの入力状態 `MouseInputState`(掴み、ホバー、ドラッグ&ドロップ、押下の遅延、カーソル)は 1 つだけ(`window.rs`)。

## 3. 新しい扱い

1. **持ち主**: 部品は最初に押した指の持ち主になる。持ち主が離れるまで、他の指はその部品に届かない(無視する)。
2. **通り道**: ある指の通り道(ウィンドウからその指が押さえている部品まで、途中で入力を横取りする部品を含む)に入っている部品は使用中とみなし、他の指が触れても無視する。
3. **ピンチ・回転**: 2 本とも同じ `ScaleRotateGestureHandler` の中にあるときだけ、今と同じく持ち主の押下を取り消して、ピンチ・回転を合成する。その外の部品に触れた指は、ピンチに加わらず独立に届く。
4. **持ち主が離れたとき**: 無視されていた指には引き継がない(離れるまで無視のまま)。ただしピンチ・回転の部品の中では、今と同じく残った指で続ける。

そのほか:
- ホバー、カーソル、ドラッグ&ドロップは主の指(とマウス)だけの機能として残す。
- 3 本目以降も同じ規則。
- マウスは「指の 1 本」として扱い、タッチと同時でも同じ規則。
- 指が 1 本だけのときの動きは今と同じ(既存のテストがそのまま通る)。

## 4. 作り方

- i-slint-core 1.18.1 のソースを `third_party/i-slint-core` に置き(ライセンス同梱)、ルートの `Cargo.toml` の `[patch.crates-io]` で差し替える。
- 変更は `input.rs` の `TouchState` と、`window.rs` の入力の配り方に限る。主でない指ごとに `MouseInputState` を持ち、指ごとに独立して `process_mouse_input` を通す。押下の前に、その指の当たる通り道が他の指の通り道と重ならないかを調べ、重なるなら無視する(規則 1・2)。
- 変更点は `third_party/i-slint-core/MULTITOUCH.md` に、どこをなぜ変えたかを書く(版を上げるときに当て直すため)。

## 5. 確認

- テスト用のクレート(`crates/multitouch-tests`)で、`slint::slint!` の小さな画面と testing backend を使い、`WindowEvent::internal(InternalEvent::Touch {..})` で指を送って確かめる:
  - 別々の TouchArea を 2 本の指で同時に押して動かせる
  - 同じ TouchArea に 2 本目が触れても無視され、状態は 1 本目のまま
  - Flickable の中のボタンを押している間、同じ Flickable の空き部分に触れた指は無視される
  - ScaleRotateGestureHandler の中の 2 本はピンチになる(今と同じ)
  - 持ち主が離れても、無視されていた指に引き継がれない
  - 1 本指の動きと、i-slint-core の既存テストが変わらない
- アプリの手動制御の面で、スティックとスライダーの同時操作を実機で確かめる(ユーザー)。
