# コントローラの画面の組み直し 設計書

- 日付: 2026-10-23
- 状態: 承認済み
- 関連: `2026-10-22-oumuamua-controller-design.md`(元の設計)、このあと petaricon 側の拡充(別の設計書)

## 1. 目的

1. 各画面を名前付きのユーザー定義UIにし、Window の直下に並べて `visible` で切り替える。petaricon で編集しやすい形にする。
2. 手動・自動の操作部品を、出力画面の上に半透明で重ねる。
3. OPPO A79 5G(2400×1080、横画面で Slint の単位でおよそ 800×360)で見切れないようにする。

## 2. 画面の構成

`main.slint` の `MainWindow` の直下に、次のユーザー定義UIの利用を並べる。1 つの画面は 1 つのファイルに置く。

| 部品 | ファイル | 表示 |
| --- | --- | --- |
| `ConnectScreen` | `connect.slint` | `visible: !connected` |
| `OutputScreen` | `output.slint` | `visible: connected`(常に下に敷く) |
| `ManualPanel` | `manual.slint` | `visible: connected && page == 1` |
| `AutoPanel` | `auto.slint` | `visible: connected && page == 2` |
| `EdgeStrip` | `strip.slint` | 常に(右端) |
| `LeaveDialog` | `leave.slint` | `visible: confirm-leave` |
| `NoticeBand` | `notice.slint` | `visible: notice != ""` |

- 画面の切り替えに `if` は使わない。画面の中の細かい出し分け(ボタンの有効・無効、ポップアップなど)は今のままでよい。
- 画面の中の状態(選んだ速度の段階など)は、画面が常にあるので、その画面の中に持ってよい。Rust とのやりとりに要るものだけ `MainWindow` のプロパティとつなぐ。
- 振る舞い(タッチ処理、タイマー、`changed`)は各画面の定義の中に置いたままにする。
- フォントは `ui/fonts/` に移し、`import "fonts/…"` で読む(petaricon のプロジェクトにそのまま入れられるように)。

## 3. 重ね表示

- `ManualPanel` と `AutoPanel` は、出力画面と同じ領域(右端の帯を除く全体)を覆う。背景は透明で、操作部品のまとまりごとに半透明の板(例: 背景色に 0.6 の不透明度)を敷き、後ろの地図が透けて見える。
- 重ね表示が出ている間、出力画面は触れない(重ね表示の全面にタッチを吸う透明の部品を敷く)。出力画面を触りたいときは右端の帯で「出力」に切り替える。
- 自動の「姿勢の指定」: `AutoPanel` に「地図で姿勢を指定」ボタンを置く。押すと出力画面に切り替わり、地図の長押しドラッグで姿勢を決める状態になる(画面上部に「長押しして向きへドラッグ」の案内と「やめる」)。指を離すと確認(x, y, 向き と「決定」「やめる」)を出し、決定で SET_POSE。自動の画面の専用の地図はやめる。

## 4. 大きさ

- 基準は 800×360(論理 px)。914×411 と 1280×720 でも崩れないこと。どの大きさでも、はみ出し・見切れ・重なりがない。
- タップの的は 44px 以上を保つ。ただし専用キーボードのキーは、画面の高さに合わせて最小 32px まで縮めてよい。
- 右端の帯: 幅 84px 前後。上から 出力/手動/自動、接続状態、接続先、全停止。360px の高さに収める。
- 出力画面: 上部の数値の帯は 1 行にまとめる(収まらない項目は省略して「…」)。地図は左、コンソールは右。
- コンソール: 専用キーボードを出している間は、コンソールが出力画面の全体に広がり(地図は隠れる)、キーボードは高さの 55% 前後を使う。
- 手動の重ね表示: 左下にスティック、右下に旋回のスライダー、中央の上寄りに速度の段階・座標の基準・左右の昇降・吸引・両方・リセットを小さくまとめる。地図の中央がなるべく見えるようにする。
- 自動の重ね表示: 左に回収(ブロック 6 個と左/右)、右に配置(3×3 と左/右)、下に移動・経路・追従・取り消し・忘れさせる・姿勢の指定。作業中の段階は上部に 1 行。

## 5. 確認

- PC 版で 800×360、914×411、1280×720 の 3 つの大きさのスクリーンショットを、接続画面・出力・手動・自動・コンソール(キーボードあり)・姿勢の指定・接続先の確認について撮り、見切れがないことを目で確かめる。
- 既存のテスト(`cargo test --workspace`)がすべて通る。重ね表示中に出力画面へのタッチが届かないこと、姿勢の指定の流れを、testing backend のテストで確かめる。
- APK を作り直す。
