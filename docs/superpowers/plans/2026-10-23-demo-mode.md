# デモモード 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ロボットも PC もなくても、APK だけで全画面を試せるよう、アプリの中で模擬のロボットを動かす「デモ」を付ける。

**Architecture:** 新しいクレート `crates/demo` に、Python の `fake_robot` + `BridgeServer` と同じ振る舞いをする小さな橋渡しサーバを Rust で書く。アプリは 127.0.0.1 の空いているポートでそれを起動し、ふだんと同じ `link::Client` でつなぐ。通信の経路も含めて本物と同じコードを通す。

**Tech Stack:** Rust 2024、proto / link クレート(既存)、std の UdpSocket とスレッド

**Spec:** `docs/protocol.md`(通信の取り決め)、`docs/superpowers/specs/2026-10-22-oumuamua-controller-design.md`(画面と停止の決まり)。振る舞いの手本は `ros/oumuamua_controller_bridge/oumuamua_controller_bridge/{fake_robot,server,supervisor,handlers,config}.py`。

## Global Constraints

- 通信は `docs/protocol.md` のとおり(1 データグラム 1200 バイト以下、CONTROL が 0.3 秒途切れたら停止、停止は解除まで続く、全停止で吸引も切る)。
- 設定値(棚の高さのボタン、速度の段階、フィールドの形、スタート位置、ブロック 6 個・棚 3×3)は `config.py` の `DEFAULTS` と同じ値にする。
- デモはアプリの中だけで動き、外のネットワークには出さない(127.0.0.1 に bind、名乗りの同報はしない)。
- コンソールは本物のシェルではなく、決まったコマンドに決まった出力を返す模擬のシェル。
- 画面の文言は日本語。

## Review Focus

1. デモ中であることが常に画面で分かる(本物のロボットにつないでいると誤解しない)。
2. デモを終えて本物のロボットにつなぎ直したとき、デモの状態が残らない(停止の固定は今の決まりどおり)。
3. デモのサーバのスレッドが、接続を切ったりアプリを閉じたりしたときに必ず止まる。

### Task 1: `crates/demo`(模擬ロボットと橋渡しサーバ)

**Files:** Create `crates/demo/{Cargo.toml,src/lib.rs,src/sim.rs,src/server.rs,src/shell.rs}`、`crates/demo/tests/demo.rs`。ルート `Cargo.toml` の members に足す。

**Interfaces:**
- Produces: `pub struct DemoRobot`。`DemoRobot::start() -> std::io::Result<DemoRobot>`(127.0.0.1 の空きポートで待ち、スレッドを立てる)、`fn addr(&self) -> SocketAddr`、`fn stop(self)`(Drop でも止まる)
- 振る舞い(Python 版と同じ):
  - HELLO/WELCOME、接続直後の CONFIG・FIELD・PATH_SHAPE(空)・TASK_MEMORY・SHELL_OPENED、STATE 20 Hz、SCAN 10 Hz(外周の壁と棚の箱への光線、1° ごと)、再送つきの確実な流れ(`link::reliable` を使う)
  - 停止: 接続直後・estop・CONTROL 0.3 秒途切れで停止、RELEASE_STOP で手動へ。停止中は昇降・吸引の入・追従の入を断る
  - 手動: CONTROL の速度で平面の模型を動かす(フィールド基準は今の向きで回す、上限 2.0 m/s・2.5 rad/s、壁は無視してよい)。jog で昇降が 0.05 m/s で動く(0〜lift_max)
  - LIFT_TO・LIFT_ZERO・SET_SUCTION・SET_TRACKER・SET_POSE・TASK_RESET・LOG_LEVEL に RESULT を返す
  - RUN_TASK: 段階を 1 秒ずつ進めて(STATE の task.step に出す)成功、TASK_DONE。回収・配置は TASK_MEMORY を更新する。作業中の次の作業は busy
  - START_PATH: 経路(CONFIG の paths の名前)を 3 秒で走って手動へ戻る。PATH_SHAPE はスタートから棚までの簡単な折れ線
  - CANCEL: 作業と経路をやめて手動へ
  - コンソール: SHELL_OPEN/INPUT/COMPLETE/CLOSE/RENAME。模擬シェルは `help`、`echo …`、`ls`、`pwd`、`date`、`ros2 topic list`(oumuamua の主なトピック名)、`ros2 node list` に答え、それ以外は `demo: <名前>: コマンドがありません`。プロンプトは `demo$ `。Ctrl+C(0x03)で `^C` と新しいプロンプト。補完はこのコマンド名から
  - ROS ログの代わりに、数秒ごとに LOG を 1 行流す(例「デモ: 車輪の電圧 24.0 V」)

- [ ] **Step 1:** `tests/demo.rs` を書く(`link::Client` で実際につなぐ): 接続して CONFIG と FIELD が届く/停止から解除して手動で前進すると STATE の x が増える/CONTROL を止めると 0.3 秒で停止/RUN_TASK が段階を経て TASK_DONE/START_PATH が 3 秒ほどで手動に戻る/停止中の LIFT_TO は失敗/シェルで `echo hi` に `hi`、Tab 補完/`stop()` でスレッドが終わる
- [ ] **Step 2〜4:** 失敗を確かめる → 実装 → `cargo test -p demo` と clippy
- [ ] **Step 5:** コミット `Add in-app demo robot`
